# ACT 输出契约提案 · 01

> 解决 `ACT-架构共识-02.md` 里"高优先未决 1"：
> **硬编码条件边如何读 AMZ 的自然语言输出。**
> 含：判断手段的四级阶梯、AMZ 六字段提案、判断边文法、全局 vs SWF 内转码的取舍。

---

## 一、先缩小问题

路由判断**不需要"结构化整个输出"**，它只需要一个**很小的信号**。

→ 所以真正的设计对象是 **「信号」，不是「输出」**。正文保持自由形式，质量不受损。

这一步缩小很关键——它一次性解掉了你担心的降智问题（见第四节）。

## 二、判断手段的优先阶梯（四级）

| 级 | 手段 | 成本 | 降智 | 适用 |
|---|---|---|---|---|
| **1** | **确定性规则** | 0 | 无 | 产物类型、字段是否为空、计数、文件是否真生成 |
| **2** | **尾部信号块**（AMZ 自报） | 0（无额外调用） | 极小 | AMZ 能自己判断路由 |
| **3** | **弱模型转码** | 1 次便宜调用 | 无 | AMZ 是黑盒 / 信号块解析失败 |
| **4** | **格式化 pipe AMZ**（短思考链） | 1 次贵调用 | 无 | 判断需要真正的语义理解 |

**原则：能用上层就别用下层。**

你列的三个选项 = 级 **2 / 3 / 4**。我补的 **级 1** 是新增的最便宜一档，而且它才是
ACT"用硬编码取代 tool use"这个哲学的**一致延伸**——既然工作流要硬编码，判断就先问
"能不能用确定性规则判"，能用就**完全不要模型**。

### 级 1 的实际覆盖面比想象中大

例：写 word 的盒子，**产出的成品类型必然是 docx**。那么"需要 word"这个判断可以退化为
**检查上一步的产物类型**，而不是问模型。

→ SWF 设计规则建议：**每条判断边必须写明它属于哪一级，且能降到级 1 的不许用级 2。**

## 三、你提的三个选项，各自的真实风险

| 选项 | 评价 |
|---|---|
| **弱智模型** | 稳、便宜。但它**只能做形状转换，做不了语义判断**。适合"把自由文本抽成字段"，不适合"判断这份方案是否完整"。 |
| **直接要求输出** | ⚠ 风险点不在"要求结构化"本身，而在**要求正文结构化**。要求整段 JSON 会挤压表达，写文档/写代码尤其明显。**限定在尾部信号块 → 降智几乎可忽略。** |
| **格式化专用 pipe AMZ** | 贵。但它有别人没有的好处：**它是隔离的**，可用极窄 prompt + 固定短思考链，**输出稳定性最好**。留给真正需要的场景。 |

## 四、AMZ 六字段（提案）

```yaml
amz:
  id: write_word
  prompt: ...            # 固定 SystemPrompt
  tools: [docx_write]    # 固定工具表（必须是能完成任务的最小集）
  permits: [...]         # 与 tools 静态绑定的权限
  model: deepseek-v4-pro # 固定模型
  output:                # ← 新增字段
    body: free           # 正文形式：保持 free，不结构化
    signal:              # 可选；仅在该 AMZ 有分支出边时需要
      fields:
        need_word: bool
        refs: int[]      # 资料标号
      encoder: self      # self | rule | weak | pipe；缺省继承全局
```

> **`tools` 必须是"能完成任务的最小集"**——这不是建议，是 CSP_AMZ 安全保证的前提
> （见 `ACT-架构共识-02.md`：CSP 只改 prompt，不提权；但工具面越宽，"只改 prompt"能造成的偏离越大）。

## 五、判断边

```yaml
edge:
  from: plan
  to: write_word
  when: signal.need_word == true
  else: review
```

**求值规则（宿主侧、确定性、无副作用）：**

- 文法限制为 `signal.<field> <op> <literal>`，`op ∈ {==, !=, in, >, <}`，可用 `and / or / not`
- **禁止函数调用、禁止模型参与求值**
- **每个"有分支的边组"必须有一条 `else`（default）边**，否则 SWF 校验不通过

## 六、解析失败怎么办

1. 缺字段 / 类型错 → **走 default 边**（宽松），不要中止
2. 只有在"连 default 也不该走"时，才升级到级 3（弱模型补一次）

→ 所以"有分支的边组必须有 default"，不只是代码风格，**它是失败策略的落点**。

## 七、全局转码 vs SWF 内转码 —— 建议两个都不选，选第三种

| | 全局统一 | SWF 内逐个设计 |
|---|---|---|
| 优点 | 改一次全局生效 | 贴合每条边 |
| 缺点 | 不同 AMZ 输出形态差异巨大，**一刀切必然有一半不合适** | 同一转码方法在 N 个 SWF 里重复定义，**改一次要改 N 处，且会漂移** |

**→ 转码器 = 全局注册的「实现」＋ SWF 内按边声明「选用哪一档」。**

SWF 只写"这条边用 `weak`"，不写"`weak` 是什么模型、什么 prompt"；要覆盖时才在 SWF 里内联定义。

**关键：这个模式 DSH 里已有现成同构。**

> `compaction-basic` 的实现是**全局**的，而 preset 决定**要不要装载、配什么阈值**。

所以 ACT 照抄这个形状即可，**不必发明新的一致性模型**。

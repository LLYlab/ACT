## 验证

```
$ node verify/check.cjs llmr.schema.json verify/write_doc.swf.json
VALID                                                        exit 0

$ node verify/check.cjs llmr.schema.json verify/negative-csp-escalation.swf.json
INVALID
   /swf/amz/0 must match "then" schema      ← CSP_AMZ 不得声明 tools
                                                             exit 1
```

**执行过程中抓出 22 处问题**（除最后一条外，全部是文字评审发现不了的）：

| 从哪来 | 缺陷 |
|---|---|
| 结构规范实测 | `tools` 被无条件 require → **每一个 CSP_AMZ 都会失败**，与"TWF 只能产 CSP_AMZ"自相矛盾 |
| 结构规范实测 | `amz:` 数组项只声明 `$ref`/`inline:` 包装 → 与示例里的**裸 AMZ 对象**不符 |
| 校验器规格 | `#1`「有未被引用的工具」**静态分析做不到** |
| 校验器规格 | `#10`「用在想省钱的位置」**无法判定** |
| 校验器测试 | `#4` 与 `#15` 对同一条边**同时开火**（既判非法又建议降级） |
| 校验器测试 | 我自己规格写的中止时机没落实（结构失败仍跑语义 → 3 条连带噪音） |
| 求值器测试 | 文法强制要求运算符 → `signal.need_docx` **写不出来** |
| 求值器测试 | 缺失 `--tools` 被报成"内部错误"；ajv `oneOf` 一次违规吐 12 条 |
| 健壮性 fuzz | 畸形输入**崩掉工具**（栈溢出 `RangeError`）而非干净报错——7 例，含求值期 1 例 |
| 库 API fuzz | `runChecks` 对畸形文档抛 **TypeError**（3 类 / 1149 例）——`\|\| []` 兜不住非数组 |
| **一致性审计** | **权威规格的检查表里没有错误码**（写的是 `W201`，实现里是 `LLMR-W201`，无法交叉核对） |
| **一致性审计** | **`LLMR-E103` 游离在检查表之外**——`#3` 原本只写"标明 `level`"，而 `level` 是 schema 的 required 字段，**这一项一直没有本体**；真正会失败的是 `when` 解析。`LLMR-E107` 也漏在表里 |
| **阶段 1 加载器** | `$ref` 引入的 AMZ 拿不到 SWF 的 `defaults.model` → **静默回退部署默认模型**。这不是 bug（defaults 刻意不作用于共享资产），是**语义坑**——已加 `LLMR-W207` |
| **阶段 2 执行器** | **加载器读不了带 UTF-8 BOM 的声明文件**——`JSON.parse` 遇到 U+FEFF 直接抛错，而 Windows 工具默认就写 BOM。已加 `stripBom`/`readJsonText` |
| **落地 WebUI** | **执行器走不了用 `$ref` 的 SWF**——它拿 `swf.amz` 直接建节点表，而 `{"$ref":"amz/xxx"}` 这种项**没有 id**，图里的节点查不到。全部测试都用内联 AMZ，所以从没撞上。已改为经 `resolveAmz` 建表 |
| **落地 WebUI** | `safePath(null)` → `path.resolve('')` 返回 **cwd**（而非报错），于是越界检查放行了凭空来的有效路径，`\|\| DIR` 兜底也被顶掉。已先挡空值 |
| **落地 WebUI** | `readBody` 把 Buffer 直接字符串拼接 → **一个多字节字符跨 chunk 边界就被截断成乱码**。已改为先收字节、最后一次性 UTF-8 解码 |
| **落地 WebUI** | `apiKey: null` 清不掉 key——`delete next.model.apiKey` 跑在 `Object.assign` **之前**，被合并又装了回去。已改为先合并、后删 |
| **暂停/恢复** | 给 `runAgt` 加了参数之后 `$('#btnRun').onclick = runAgt` 把 **PointerEvent 当成了 `startAt`**，点一下就报「节点不存在：[object PointerEvent]」。已包一层。**这类错只有真的点下去才会露出来** |
| **作业 SWF** | 表单是「有 args 就不给诉求框」的二选一 → 用户**没地方贴老师那段话**，而第 1、2 步全靠它。已改为诉求永远在 |
| **作业 SWF** | `paintAgt` 里留下了两个 `<div id="runBox">`（编辑时重复追加）——重复 id，前端永远只认第一个 |
| **项数审计（新）** | **给审计加了「检查项数必须一致」之后，它第一次运行就抓出 11 处漂移**——文档里同时写着 15 项、16 项、17 项。没人改错，只是**此前没有任何东西在管这个数字**。已把项数的真值收进 `checks.cjs` 的 `CHECKS`，并让审计逐文件比对 |
| **环检测（新）** | 环检测初版只扫「从入口可达」的节点 → **环若包含入口，入口就不再唯一，`LLMR-E107` 先响，环反而不报**。用户看到的是「入口不唯一」这个症状，不是「图里有环」这个病因。已改为**无唯一入口时扫全图**（自测 5 例抓到） |
| 读文档 | `LLMR-设计规格.md` §13.3 的「码空间」说明**重复了两遍**——同一段话印两次，改一处会漏另一处。（**唯一一处不是执行抓出来的**） |

→ 印证设计原则 #8：**规格的缺陷只能靠执行暴露。**
> 注意最后一条是这 22 处里唯一的例外，而它恰好是"人读文档"能抓到的**格式**问题，
> 不是**语义**问题——这条原则依然成立。

### 一致性审计：码空间 + 项数

```
$ node tools/validator/auditcodes.cjs
实现 23 个码 · 来源 tools/validator/checks.cjs + tools/validator/validate.cjs
✓ LLMR-校验器规格.md  23 个码，与实现完全一致
✓ LLMR-设计规格.md  23 个码，与实现完全一致

实现 17 项检查 · 来源 checks.cjs 的 CHECKS
✓ CHECKS 登记齐全  20 个语义码
✓ LLMR-设计规格.md §13.3  17 行，编号连续
✓ 所有文档的项数与实现一致（17 项）
码空间一致性: 通过
```

三件事被机器对齐：

1. **码空间**：把实现的码与两份规格对做差集——**任何一份漏了码，或写了实现里不存在的码，都会露出来**。
2. **`CHECKS` 与实现**：实现里出现的语义码，必须在 `CHECKS` 里登记；反过来也查。
   （防的是"加了检查却忘了登记"——`LLMR-E103` 当年就是这样游离在表外的。）
3. **项数**：`CHECKS.length` 是唯一真值。设计规格 §13.3 的表行数必须等于它，
   所有散文里写的「N 项检查」也必须等于它。

> 第 3 条是后加的，而它**第一次运行就抓出 11 处漂移**——文档里同时写着 15 项、16 项、17 项。
> 没人改错，只是此前没有任何东西在管这个数字。
>
> 这就是为什么这条审计值得保留：文档集有 9 份文件、5 份已废弃，**单靠人读一定会漂**。
> 码空间与项数是仅有的两个能被机器对齐的接缝——那就把它们都对上。
>
> `docs/history/` 被排除在项数检查之外：归档旧规格里的数字是"它自己当时的"，不是对现在的断言。

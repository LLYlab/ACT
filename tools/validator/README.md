# LLMR 校验器（阶段 0）

实现依据：`../../LLMR-校验器规格.md`。
**零依赖切片**——不碰 DSH 运行时、不装载任何插件、只读文件。是三方共用件：作者发布门槛 / 用户本地助手 / 导入安全审查。

---

## 用法

```bash
node validate.cjs <target.swf.json> [选项]
```

| 选项 | 说明 |
|---|---|
| `--schema=path` | 结构规范，默认 `../../llmr.schema.json` |
| `--mode=author\|export\|import` | 默认 `author`。`import` 会校验 `_review.surfaceHash`；`export` 会拒绝残留 `$ref` |
| `--lib=dir` | AMZ 库目录，用于解析 `$ref: amz/xxx` |
| `--tools=json` | 工具名数组（`["read","write"]` 或 `{"tools":[…]}`），用于检查 `tools` 引用存在性 |
| `--pages=json` | UI 页面组名数组，用于检查 `ui.page` |
| `--json` | 输出 JSON（供工具消费） |

**退出码**：`0` 通过 · `1` 有错误 · `2` 用法/读取错误。

### 例

```
$ node validate.cjs ../../verify/write_doc.swf.json
LLMR 校验器 · mode=author
目标: …\verify\write_doc.swf.json

能力表面  sha256:61b9ed8f…
  plan_outline     tools=[]  guards=[]
  write_plain      tools=[]  guards=[]
  write_word       tools=[docx_write]  guards=[]

结果: 通过（0 错误 / 0 警告）
```

| 文件 | 职责 |

## 实现中修掉的五处规格缺陷

**1. 文法强制要求运算符** —— 原文法 `atom := IDENT op literal` 不接受
`signal.need_docx` 这种裸布尔字段，而那恰恰是最常见的判断形状
（"规划器说要不要 docx"），作者被迫写 `signal.need_docx == true`。
改为 `atom := IDENT [op literal]`；省略时该字段**必须是 `bool`**，否则 `LLMR-E106`。

**2. #1 原定义不可计算** ——"某 AMZ 有未被任何边/产物类型引用的工具"静态分析做不到。
改为工具类别配对：`LLMR-W201`（含 `exec`）、`LLMR-W206`（`exec` + `artifact` 并存），直接对应 CSP 的安全前提。

**3. #4 与 #15 会同时命中同一条边** ——`level:2` 且只用确定性变量时，
`#15` 判它非法（错误）、`#4` 建议降级（警告），**同一输入既错又只是建议**，自相矛盾。

按**修复动作归一**：

| 输入 | 报 |
|---|---|
| `level:1` 且含 `signal.` | `LLMR-E104`（错误） |
| `level:2-4` 且**全是**确定性变量 | **只报 `LLMR-W202`**（修法 = 把 level 改成 1） |
| `level:2-4` 且**混用** `signal.` 与其它 | `LLMR-E104`（错误） |

自测里有一条专门守这个回归：`#4 … 只报 W202，不报 E104`。

**4. 畸形输入会崩掉工具（栈溢出）** —— fuzz 实测：深度嵌套的 `((((…`、
`not not not…`、超长 `and` 链会以 `RangeError: Maximum call stack size exceeded`
抛出——**不是 `ParseError`**。其中 1 例发生在**求值期**（`and` 链解析得了，但求值时沿左脊递归爆栈）。

对一件要消费**陌生人手写文件**的工具，这是安全属性问题，不是体验问题：
一份坏文件不该把工具打崩，而该给出一份可诊断的错误。

修法：解析期设上限（长度 8192 / 嵌套深度 128 / 条件项 256），超出即 `ParseError`。
这组上限同时界定了 AST 深度，`evalNode` / `walk` 的递归也一并安全。

> 修前 7 例异常 → 修后 **0 例**，18249 份畸形输入全部干净拒绝。

**5. `runChecks` 会抛 TypeError（库 API 不是全函数）** —— `checks.cjs` 是导出给
「阶段 1 加载器」「编辑器」直接调用的，**不保证经过 CLI 的 schema 前置门**。
实测 3 类崩溃、1149 例：

| 输入 | 崩溃 |
|---|---|
| `swf` 为 `null` / 非对象 | `Cannot read properties of null (reading 'amz')` |
| `swf.amz` 不是数组 | `(swf.amz \|\| []).forEach is not a function` |
| `swf.order` 不是数组 | `(swf.order \|\| []).map is not a function` |

修法：入口加一层**归一**（`asObject` / `asArray`），并对 AMZ 项做类型守卫。
`|| []` / `|| {}` 这种写法看着像在兜底，其实**只在值是 `undefined`/`null` 时才兜底**——
值是个字符串或数字时它原样穿过，然后在下一行炸掉。

> 修前 1149 例崩溃 → 修后 **0 例**，16090 份畸形文档全部返回报告。

## 环检测（第 17 项，`LLMR-E113`）

执行器有 `max-steps` 兜底，但那是**运行期**才发现，代价是烧掉一整条轨迹。
环是纯静态就确定的事，所以它被前移到了校验期。

**两处形状上的讲究：**

1. **起点集合取决于有没有唯一入口。**
   有唯一入口 → 只看从入口可达的部分（不可达节点上的环永远跑不到，且已被 `W203` 标出）。
   没有唯一入口 → **扫全图**。
   后面这条不是多余：环若**包含入口**，入口就不再唯一，`E107` 会先响——
   那时若就此收手，用户看到的是「入口不唯一」这个**症状**，而不是「图里有环」这个**病因**。

   > 初版只扫 `reach`，自测第 2 例当场暴露了这个漏诊。

2. **用显式栈的迭代 DFS，不用递归。**
   图的规模由文档决定，一份超长直链能把递归 DFS 直接压爆调用栈——
   这个项目已经因为「畸形输入压爆调用栈」吃过一次亏（见本文第 4 条）。
   回归测试在 `schemfuzz.cjs`：**5 万节点的直链与首尾成环，都必须无异常返回**。

同一个环会被不同起点重复发现，所以把环**旋转到最小 id 打头**后去重；最多列 5 个，其余只报个数。

## 项数的真值在代码里（`CHECKS`）

`checks.cjs` 导出 `CHECKS`——17 项检查的编号、码、名称。

**为什么单独列一份**：文档里到处写「N 项检查」，每加一条检查这些数字都要人肉去改，
结果实测同时写着 **15 项、16 项、17 项**三个数字，散在 9 份文件里。

`auditcodes.cjs` 现在拿 `CHECKS.length` 当真值，去比对：
- 设计规格 §13.3 的表行数；
- 所有散文里「N 项检查」「检查（N 项）」「校验规则（N 项）」的写法（含中文数字）；
- 实现里出现的语义码是否都已在 `CHECKS` 登记。

> 加检查的正确姿势因此只有两步：**在 `CHECKS` 加一行 + 在规格表里加一行**。
> 忘了哪一步，审计都会失败。

## 管线行为

**结构校验失败 → 中止，不跑语义检查**（规格 §2）。

理由已实测：负例夹具（CSP 越权）结构失败后若继续跑语义，会**额外冒出 3 条**
`E106` / `E111` / `E107` —— 全是那个破损 AMZ 的连带噪音，不是独立问题。

**`oneOf` / `anyOf` 的分支错误按 `instancePath` 折叠**：同一路径只报一条，
优先保留带 `failingKeyword` 的那条（它指向真正失败的条件分支）。
同一个负例从 **12 条降到 1 条**：

```
LLMR-E001  /swf/amz/0
    must match "then" schema
    → failingKeyword=then；同路径另有 8 条分支错误已折叠
```

## 边界

**做**：结构约束（JSON Schema）、17 项语义检查、能力表面 + 防篡改哈希。
**不做**：不执行 SWF、不装载 AMZ、不接触 DSH 运行时。

`expression.cjs` 里的 `evaluate()` 是**运行时求值器**的同一份实现，
将来阶段 2 的条件边求值可直接复用——但**校验期间不调用它**（校验是静态的）。

> 求值失败（字段缺失/类型不符）在校验期是 `E106`；
> 在运行期则是"走 `else`"，**不是错误**。两者刻意区分。
